# Implementation Register

## Mission 300 Programme and Implementation Register Specification

## A. Headline Performance Cards

The register combines programmes, projects, milestones and actions while preserving their different record types.

| Pillar or Scope | Metric or Dashboard Element | Visual Type | Target or Benchmark | Target Comparison and Progress Behaviour | Information Icon Content: Definition, Methodology and Data Source |
|---|---|---|---|---|---|
| Delivery tracking | Active programmes and projects | Summary card with programme and project counts separated | No formal target; approved current register portfolio | Compare with the previous reporting cycle and identify newly added or closed records. | Definition: Approved active programmes and projects in the register. Methodology: Count unique active programme records and unique active project records separately. Data source: Implementation Register and institutional project registers. |
| Delivery tracking | Priority milestones delivered on time | Progress card | 100% of due priority milestones delivered on time | Compare with the previous reporting cycle and show due, completed, delayed and blocked counts. | Definition: Priority milestones completed by their due dates. Methodology: On-time completed priority milestones divided by priority milestones due by the selected date, multiplied by 100. Data source: Compact Progress Report and Implementation Register. |
| Delivery tracking | Delayed or blocked records | Exception card | Zero delayed or blocked priority records | Compare with the previous reporting cycle. A decline is positive. | Definition: Approved priority records currently delayed or blocked. Methodology: Count unique register records with current status Delayed or Blocked. Data source: Implementation Register. |
| Delivery tracking | Records requiring evidence or update | Exception card | Zero overdue priority records without current evidence or update | Compare with the previous reporting cycle and show days since last update. | Definition: Priority records missing required evidence or a current update. Methodology: Count records whose evidence field is missing or whose required update date has passed. Data source: Implementation Register and evidence log. |

## B. Programmes

| Pillar or Scope | Metric or Dashboard Element | Visual Type | Information Icon Content: Definition, Methodology and Data Source |
|---|---|---|---|
| Programmes | Programme register | Searchable programme table | Definition: Mission 300-relevant programmes and initiatives. Methodology: Show programme identifier, name, lead and supporting institutions, pillar, objectives, financing where held, status, priority, dates, bottlenecks and last update. Data source: Implementation Register and institutional programme records. |

## C. Projects

| Pillar or Scope | Metric or Dashboard Element | Visual Type | Information Icon Content: Definition, Methodology and Data Source |
|---|---|---|---|
| Projects | Project register | Searchable project table with profile drill-down | Definition: Projects linked to programmes, pillars and indicators. Methodology: Show project identifier, programme, owner, location, coverage, lifecycle stage, financing where held, status, dates, evidence and bottlenecks. Data source: Project Register and institutional project records. |

## D. Milestones and Actions

| Pillar or Scope | Metric or Dashboard Element | Visual Type | Information Icon Content: Definition, Methodology and Data Source |
|---|---|---|---|
| Milestones | Milestone tracker | Timeline and status table | Definition: Time-bound outputs or decision points linked to delivery records. Methodology: Show expected and actual dates, status, lead institution, evidence, risk and next action. Data source: Compact Progress Report, Milestone Evidence Log and Implementation Register. |
| Actions | Implementation action tracker | Action table with owner and due date | Definition: Specific actions required to progress a programme, project or reform. Methodology: Track responsible institution, due date, status, priority, dependency, next action and evidence. Data source: Compact Progress Report and Implementation Register. |

## E. Import, Export and Record Linkages

| Pillar or Scope | Metric or Dashboard Element | Visual Type | Information Icon Content: Definition, Methodology and Data Source |
|---|---|---|---|
| Register operations | Structured import and validation | Template upload with error report | Definition: Import of approved programme, project, milestone and action templates. Methodology: Validate schema, identifiers, controlled values, required fields, dates and duplicates before accepting a new version. Data source: Approved Compact Progress Report and implementation-register templates. |
| Register operations | Filtered export and technical handoff | Export action | Definition: Export of the current filtered register. Methodology: Preserve filters, record identifiers, source references, version, validation status and export date. Data source: Implementation Register. |
