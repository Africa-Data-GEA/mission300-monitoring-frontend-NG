# Reports & Exports

## Mission 300 Reports and Exports Module Specification

## A. Report Catalogue

This is a report-generation module. It does not require target-comparison columns.

| Pillar or Scope | Metric or Dashboard Element | Visual Type | Information Icon Content: Definition, Methodology and Data Source |
|---|---|---|---|
| Compact reporting | Compact Progress Report and Compact review export | Report cards | Definition: Structured Compact progress and review outputs. Methodology: Generate from approved indicator values and implementation records using the selected reporting period and filters. Data source: Key Performance Indicator repository, Compact Progress Report and Implementation Register. |
| Performance reporting | Pillar, Key Performance Indicator, baseline-current and target-actual reports | Report cards | Definition: Performance reports at pillar and indicator level. Methodology: Preserve selected indicators, periods, units, baselines, targets, current values, validation status and source notes. Data source: Key Performance Indicator catalogue and value repository. |
| Delivery reporting | State and Distribution Company, implementation, bottleneck and financial reports | Report cards | Definition: Geographic, utility, delivery, exception and investment outputs. Methodology: Generate from the corresponding filtered dashboard modules and preserve the exact applied filters. Data source: Distribution Company data, Implementation Register, Bottleneck Register and financing records. |
| Data-governance reporting | Submission-compliance and data-quality reports | Report cards | Definition: Reports on institutional submission and validation performance. Methodology: Summarise expected, received, overdue, approved, returned, rejected and missing records by selected period. Data source: Submission and Validation Registers. |

## B. Generate Report

| Pillar or Scope | Metric or Dashboard Element | Visual Type | Information Icon Content: Definition, Methodology and Data Source |
|---|---|---|---|
| Report generation | Report configuration and preview | Configuration panel with preview | Definition: User-defined report output. Methodology: Select report type, period, pillar, category, state, Distribution Company, programme, agency, validation status, readiness tier and export format, then preview before generation. Data source: Reports configuration and linked module data. |
| Report generation | Report metadata and source notes | Report header and appendix | Definition: Context required to interpret generated outputs. Methodology: Include report title, reporting period, applied filters, generation date, data version, source notes, validation status, units and limitations. Data source: Report configuration and underlying data records. |

## C. Saved Reports

| Pillar or Scope | Metric or Dashboard Element | Visual Type | Information Icon Content: Definition, Methodology and Data Source |
|---|---|---|---|
| Saved reports | Saved configurations and generated-report history | Searchable table | Definition: Reusable report settings and previously generated outputs. Methodology: Store configuration owner, report type, filters, created date, last generated date, format and file reference. Data source: Reports and Exports repository. |

## D. CPR and Compact Export

| Pillar or Scope | Metric or Dashboard Element | Visual Type | Information Icon Content: Definition, Methodology and Data Source |
|---|---|---|---|
| Compact export | Compact Progress Report export | Structured export action | Definition: Compact Progress Report-aligned output for review. Methodology: Map approved action, milestone, status, evidence, risk, next action and verification fields to the agreed export structure. Data source: Compact Progress Report Master and Milestone Evidence Log. |
| Compact export | Implementation Register export | Structured workbook export | Definition: Filtered programme, project, milestone and action records. Methodology: Preserve identifiers, linkages, statuses, dates, evidence, versions and validation status. Data source: Implementation Register. |
